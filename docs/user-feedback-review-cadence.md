# User Feedback Review Cadence

## Daily During Beta

- Check new in-app feedback.
- Flag security, privacy, or broken-core-flow reports.
- Respond manually only when contact details are available and appropriate.
- Convert clear bugs into draft issues.

## Weekly

- Review open feedback by priority.
- Merge duplicates.
- Update the product improvement backlog.
- Pick one small improvement sprint.
- Update release notes after verified changes.

## Monthly

- Look for repeated user friction.
- Review analytics trends alongside feedback.
- Revisit onboarding, resume upload, job matching, application tracker, interview coach, and pricing pages.
- Archive closed feedback that no longer needs action.

## Rules

- Feedback is evidence, not automatic product direction.
- Do not expose private resumes, emails, or application details in public issues.
- Do not promise release dates before work is scoped.
