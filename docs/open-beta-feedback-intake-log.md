## 🏷️ Severity and Type Reference

### Feedback Types
- **BUG:** Functional error where the application does not work as specified.
- **UX/UI:** Visual flaws, styling issues, alignment, or cognitive friction in routing.
- **FEATURE:** A request for new functionality or enhancements.
- **COPY:** Typos, misleading language, or missing disclaimers.

### Severity Levels
- **🔴 P0 (CRITICAL):** Blocks signup, logins, or exposes security concerns. Requires immediate hotfix.
- **🟡 P1 (HIGH):** Breaks a major user feature with no alternative path.
- **🔵 P2 (MEDIUM):** Non-blocking bugs, UI/UX issues, or localized errors.
- **🟢 P3 (LOW):** Aesthetic adjustments or suggestions.

## 🔄 Intake Instructions

1. When a user reports feedback via the `/feedback` form, GitHub issues, or support channels, extract the details.
2. Assign a unique **Feedback ID** (e.g. `OBF-01`, `OBF-02`).
3. Fill in the columns accurately based on the user's actual experience.
4. Set **Status** to `New`, `Triaged`, `In Progress`, `Deferred`, or `Resolved`.
5. Link any corresponding issues or commits in the **Next Action** column.
