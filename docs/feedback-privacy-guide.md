# Feedback Privacy Guide

Feedback can include private career information, so it must be handled carefully.

## Stored Data

- User id.
- Feedback type.
- Rating.
- Message.
- Page or workflow.
- Optional contact email.
- Status, priority, labels, and admin notes.

## Privacy Rules

- Do not place private resumes, phone numbers, email addresses, application notes, or recruiter names in public GitHub issues.
- Summarize sensitive feedback before issue creation.
- Keep contact details inside the app/admin context unless the user explicitly provided them for follow-up.
- Treat security and privacy feedback as high priority.
- Delete account workflows should include feedback records in privacy cleanup.

## Admin Handling

- Use issue drafts as starting points only.
- Review every draft before copying it into GitHub.
- Remove private information first.
- Link public issues back to internal feedback only when it is safe.
